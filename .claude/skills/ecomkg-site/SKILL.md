# Сайт ECOM KG (проект ACTBL)

Статический многостраничный сайт цифровой платформы электронной торговли и логистики
Кыргызстана. Платформа называется **ECOM KG**, создатель — **ACTBL**. Чистый HTML/CSS/JS
без сборки; авторизация и роли — через **Supabase**. Хостинг — **Vercel** (автодеплой из GitHub).

## Что где (карта проекта)

- `index.html` — главная (корпоративный дизайн: hero с фото гор, экосистема, каталог,
  карта торговых путей, роли, партнёры, CTA).
- Разделы по ТЗ: `about.html`, `membership.html`, `catalog.html`, `education.html`,
  `events.html`, `committees.html`, `news.html`, `knowledge.html`, `suppliers.html`.
- Новость: `article.html?id=1..6`. Юр. страницы: `offer.html`, `privacy.html`.
- Входы (у каждой роли свой): `login.html` (клиент), `partner-login.html`, `admin-login.html`.
- Кабинеты (защищены по роли): `cabinet.html` (client), `partner.html` (partner), `admin.html` (admin).
- Регистрация: `register.html` (создаёт клиента).
- `css/style.css` — вся дизайн-система (токены в `:root`).
- `js/main.js` — вставляет ОБЩИЕ шапку и подвал на всех страницах + меню «Ещё» +
  переключатель языка + демо-обработчики форм.
- `js/supabase-config.js` — 2 ПУБЛИЧНЫХ значения (URL + publishable key). Секреты сюда НЕ пишем.
- `js/auth.js` — авторизация (`window.ecomAuth`).
- `supabase-setup.sql` — SQL для таблицы ролей `profiles` (запускается один раз в Supabase).
- Служебное: `design-preview-v2.html` (сравнение старых дизайн-направлений), README.md,
  `ШАБЛОН_сайта_с_нуля.md`.

## Ключевое соглашение: одна правка → весь сайт

Шапка и подвал НЕ дублируются в страницах. В каждой странице есть только
`<div id="header"></div>` … `<div id="footer"></div>`, а `js/main.js` подставляет их.
**Поэтому меню, логотип, язык, подвал меняются в ОДНОМ месте — `js/main.js`.**
Дизайн (цвета/шрифты/карточки/кнопки) меняется в ОДНОМ месте — `css/style.css`, потому что
все страницы используют общие классы. Правя токены в `:root`, ты перекрашиваешь весь сайт.

Каждая страница: `<link rel="stylesheet" href="css/style.css">`, в конце `<script src="js/main.js"></script>`,
у `<body data-page="имя.html">` (подсветка активного пункта меню).

## Дизайн-система (референс «E-COM», корпоративный)

Тёмно-синий + белый + акцентный синий. Шрифт Inter. Токены в `css/style.css :root`:
`--navy:#0d2340; --navy-2:#13345c; --navy-3:#081a30; --blue:#2f6fed; --blue-soft:#eaf1fd;
--alt:#f3f6fb; --text:#111c2e; --muted:#5d6b7d; --border:#e4e9f0;`.
Готовые классы (переиспользуй, НЕ выдумывай новые без нужды):

- Секции: `section` (белая), `.section-alt` (светло-голубая), `.section-navy` (тёмная).
- `.hero` (фон-фото + `.hero-bg` + overlay), `.page-banner` (тёмный баннер внутренних страниц).
- `.overline` (надзаголовок), `.head-split` (заголовок слева + текст справа), `.sec-head` (по центру).
- Сетки `.grid.g2/.g3/.g4`, карточки `.card` (с `.ico`), плитки `.tiles > .tile`.
- Кнопки: `.btn` + `.btn-primary` (navy), `.btn-accent` (синий), `.btn-outline`,
  `.btn-light` (белая, для тёмного фона), `.btn-ghost` (прозрачная на тёмном), `.btn-sm`.
- `.checks` (список с синими маркерами), `.tag`, `.badge`, `.count`, `.notice`, статусы `.status.st-ok/.st-wait/.st-new`.
- Кабинеты: `.dash` (`.dash-menu` + контент), `.kpi`, таблицы.
- Формы: `.form`, `.field`. Ошибка входа: `.auth-err.show`, успех: `.auth-ok`.
- Вход: `.auth-wrap` (2 колонки), `.auth-side` (брендовая панель), `.segmented` (вкладки),
  `.auth-center`/`.auth-card` (админ-вход, центрированная карточка).

Меню в шапке: 6 основных пунктов + выпадающее `.has-drop`/`.drop` («Ещё»), центрировано
(`.nav-links{flex:1;justify-content:center}`), при ≤1200px сворачивается в бургер.
Переключатель языка — `.langsel` (кнопка глобус+флаг+▾ → список языков), есть и в подвале (`.up`).

Фото — бесплатные с Unsplash (`https://images.unsplash.com/photo-ID?w=..&q=80&auto=format&fit=crop`).
Перед использованием НОВОГО фото проверь, что URL отдаёт 200 (`curl -I`), иначе будет битая картинка.

При заметных изменениях дизайна сверяйся с навыком `frontend-design` (не делать шаблонно).

## Авторизация и роли (Supabase)

`js/auth.js` даёт `window.ecomAuth`:
- `ecomAuth.signIn(email, password, expectedRole, onErr)` — вход; если роль не совпала, выкидывает.
- `ecomAuth.signUp(email, password, fullName, onOk, onErr)` — регистрация (роль всегда `client`).
- `ecomAuth.guard(requiredRole)` — ставится в `<head>` защищённой страницы, пускает только нужную роль.
- `ecomAuth.signOut()` — выход.
- Если `js/supabase-config.js` пуст → **демо-режим** (входы просто ведут в кабинеты, guard не блокирует).

Роли: `client` (по умолчанию, регистрируется сам), `partner`, `admin` (назначает владелец
вручную: Supabase → Table Editor → `profiles` → поле `role`). У каждой роли своя страница входа.
Защита реальная (сервер + RLS в Supabase), а не только JS.

**Добавить защищённую страницу:** в `<head>` после стилей подключи
`js/supabase-config.js`, `js/auth.js`, затем `<script>ecomAuth.guard('client'|'partner'|'admin')</script>`;
в меню кабинета добавь `<a href="#" onclick="ecomAuth.signOut();return false;">🚪 Выйти</a>`.

Секретные ключи (`service_role`, пароль БД) НИКОГДА не попадают в код/сайт/чат. В сайте только
Project URL и publishable/anon key — они публичные по дизайну.

## Локальный предпросмотр (важный нюанс)

Папка проекта содержит кириллицу и пробел («сайт actbl»), из-за чего Ruby WEBrick падает
(`invalid byte sequence`). Поэтому для локального сервера копируй в ASCII-путь:

```bash
rm -rf /tmp/ecomkg_site && cp -r "<ПАПКА ПРОЕКТА>" /tmp/ecomkg_site
cd /tmp/ecomkg_site && LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 ruby -run -e httpd . -p 8777 >/tmp/site.log 2>&1 &
```

Открывай `http://localhost:8777/...` в браузер-превью. После проверки: `pkill -f httpd; rm -rf /tmp/ecomkg_site`.
На этой машине нет node/python/pandoc — используй ruby/perl/curl. Просто открыть `index.html`
файлом тоже работает в реальном браузере (шрифты/фото грузятся из интернета).

## Деплой (GitHub → Vercel)

Репозиторий: `git@github.com:salahunovmarsel-ops/actbl.git` (ветка `main`). Живой сайт:
`https://actbl-green.vercel.app`. Vercel пересобирает автоматически при пуше в `main`.
Владелец правит `js/supabase-config.js` сам через веб-редактор GitHub (ключи в чат не передаются).

Когда пользователь говорит «залей на GitHub» / «обнови сайт»:
```bash
cd "<ПАПКА ПРОЕКТА>" && git add -A && \
git -c user.name="ECOM KG" -c user.email="zusupovnuni@gmail.com" \
  commit -q -m "<что изменено>" && git push origin main
```
Коммить/пушь только по просьбе. Через ~минуту сайт обновится; напомни про Cmd+Shift+R (сброс кэша).

## Типовые задачи (рецепты)

- **Новая обычная страница:** скопируй шаблон внутренних (`<head>` со style.css; `#header`;
  `.page-banner` с крошками и `<h1>`; контент из общих классов; `#footer`; `main.js`).
  Добавь `<meta name="description">`. Если нужна в меню — добавь в массив `primary`/`more` в `js/main.js`.
- **Изменить цвета/шрифт всего сайта:** правь токены в `css/style.css :root`.
- **Добавить пункт меню:** массивы `primary` (видимые) и `more` (в «Ещё») в `js/main.js`.
- **Демо-действие (форма/заявка):** формам ставь `data-demo`, кнопкам-заявкам `data-req` —
  `main.js` покажет сообщение (реальные сервисы подключаются позже, этапы 2–3 ТЗ).
